# 业务规则

1. 固定任务和用户锁定任务不得移动。
2. 计划项不得时间重叠。
3. 跨地点相邻任务之间必须留出通勤时间。
4. 通勤默认采用高德步行时间；用户明确说自行车或电瓶车时采用高德对应
   非机动车路线时间。
5. 实际通勤与校园拥堵时段重叠时必须增加结构化缓冲，并用扩展后的时间
   校验后续任务；高峰期不强制避开，只提供可选错峰建议。
6. 固定课程、最早开始、最晚结束、截止时间和开放时间高于一切软偏好。
7. 有 DDL 的任务必须在 DDL 前结束。
8. 有开放时间约束的地点只能在开放时段内安排任务。
9. 无法安排的任务必须明确列出，不得静默删除。
10. 重规划最多两轮。
11. 外部数据失败时必须标注降级来源，不得伪造实时数据。
12. 只有通过全部硬约束的计划才能成为当前计划。
13. 调整类请求必须保留调整前计划，并生成任务级差异。
14. 已知天气风险与室外任务重叠时，应重新规划而不只是生成提醒。
15. 演示状态复位只清除演示用户数据，不得修改知识库和静态数据。
