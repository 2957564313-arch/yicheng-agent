## 一、项目一句话定位

易程智策是一款面向杭州电子科技大学学生学习与生活场景的校园时空规划
智能体。它能够理解学生用自然语言描述的课程、学习、会议、取件、运动和
生活安排，融合个人课表、校园开放规则、地点通勤、天气与长期偏好，生成
可执行日程，并在需求或环境变化时完成校验和局部调整。

## 二、应用场景

### 1. 一日多任务规划

学生同时有课程、自习、实验报告、取快递、用餐和运动等任务，系统将固定
课程锁定为硬约束，再结合地点、时长、截止时间和通勤安排剩余任务。

### 2. 一周目标拆解

学生可以描述一周内的多个目标、总时长、阶段依赖、重复次数、截止时间和
偏好时段。系统把目标拆成每天可执行的时间块，并在容量不足时明确指出
缺口，不通过压缩任务或隐藏任务制造“看似可行”的方案。

### 3. 突发变化后的动态调整

面对临时调课、会议延长、任务新增、天气变化或某项任务取消，系统保留
已完成任务和用户锁定任务，只重排受影响部分，并展示调整前后差异。

### 4. 校园规则与制度问答

系统可回答场馆开放、宿舍门禁、快递点、阳光长跑、校医院以及学生手册
中的学籍制度问题。服务时间优先使用结构化核验规则；学生手册回答保留
原文件、页码和章节来源，数值、期限与例外条件不交给模型自由改写。

### 5. 个性化长期使用

每位用户可以连接杭电助手，同步个人课程、考试、图书馆预约与二课安排，
并维护常用地点、出行方式、作息和学习偏好。日程可以导出为带闹钟的系统
日历；网页打开时还可使用浏览器通知。

## 四、核心功能

### 1. 自然语言需求理解

- 提取日期、时间、地点、时长、截止时间、顺序、交通方式和偏好；
- 理解“第几节有课”“下课后”“保持原时间”“顺延半小时”等校园表达；
- 信息不足时提出一个可操作的澄清问题；
- 复杂请求中不遗漏用户提出但暂时无法安排的任务。

### 2. 个人课表硬约束

- 导入个人课表并按学期开始日期换算周次、单双周和具体日期；
- 课程开始、结束时间由已核验节次表换算；
- 固定课程不可移动、不可压缩；
- 法定节假日、调休工作日与学校补课或停课分层处理，不猜测学校安排。

### 3. 校园时空联合规划

- 查询校园地点并计算步行、骑行或电动车通勤；
- 用户未指定交通方式时默认按步行时间；
- 校园拥堵时段增加通勤余量并提醒，但不强制用户避开；
- 同时校验截止时间、场所开放、通勤、天气和任务完整性。

### 4. 规划—校验—调整闭环

- 先生成候选计划，再进行确定性硬约束检查；
- 日级重排采用有界全局搜索，先保证任务完整和硬约束，再依次最小化
  移动任务数、总位移、通勤与偏好代价；
- 无法全部安排时保留可安排部分，明确显示未安排任务和真实缺口；
- 校验失败时返回具体冲突，不再无效重复运行同一个确定性规划器；
- 周计划发生完成、延期、新任务、固定事件或天气变化时生成新版本，
  冻结已完成、锁定和已开始时间块，并保留跨版本血缘。

### 5. 校园知识增强检索

- 按服务规则、学生手册和个人课表分域检索；
- 对同义问法进行归一和查询扩展；
- 采用候选召回、来源分级、二阶段重排、数值答案优先和相似证据去重；
- 学生手册 PDF 按页码和页内章节切分，避免跨章节拼接；
- 场馆开放等规划硬约束优先使用结构化规则；
- 对学籍期限、资格和例外条款采用确定性引用，防止模型改写关键数字。

### 6. 长期日程、提醒和关怀

- 聚合课程、当前计划、长期记忆和用户作息；
- 为早课生成起床和出发提醒；
- 为会议、自习、运动、取件和就寝生成提前提醒；
- 连续高强度学习时给出用餐、休息、运动和情绪照顾建议；
- 个性化建议必须由用户主动开启，只征求确认，不自动插入任务；
- 用户连续拒绝某类建议后自动降频。

## 五、功能特色与创新点

### 创新一：校园知识驱动的时空硬约束规划

系统不是只生成一段日程文本，而是把个人课表、校园节次、场所开放、任务
地点、通勤时间、天气和截止时间放入同一计划状态中，由程序逐项验证。

### 创新二：可验证的规划—校验—动态重排闭环

智能体在生成计划后必须通过任务完整、时间不冲突、通勤充足、截止时间、
场所开放和天气风险检查。发生变化时使用词典序最小扰动目标，不推翻无关
安排；每次周级调整都保留旧版本、触发原因、移动数、保留率和来源时间块，
结果既可解释也可复核。

### 创新三：对话规划与长期日程相结合

用户既可以通过对话生成和修改日程，也可以导入课表、维护长期偏好、查看
日程汇总、接收提醒并导出系统日历，使智能体从一次性问答延伸到日常使用。

### 创新四：面向高校制度的可审计增强检索

检索结果保留来源、页码和章节。开放时间、制度期限和例外条款设置确定性
保护层，避免模型在自然语言润色中丢失数字或混入无关章节。

## 六、技术实现说明

技术框架只用于解释实现，不作为项目宣传主线。

| 层级 | 当前实现 |
|---|---|
| 用户入口 | 响应式单页 Web |
| 服务接口 | FastAPI |
| 智能体编排 | LangGraph 五节点有状态流程 |
| 自然语言模型 | qwen3.7-plus，配置备用模型链 |
| 精确计算 | Python 分层约束排程、硬校验和有界全局最小扰动搜索 |
| 校园知识 | 结构化规则 + 本地增强检索 |
| 地图与天气 | 高德 Web 服务，带缓存、限速和降级 |
| 用户数据 | SQLite；公网测试版辅以浏览器快照和个人数据包 |

五个节点为：理解需求、补充校园上下文、生成计划、检查硬约束、组织回复。
周层另负责目标—阶段—时间块分配，日层负责把时间块结合课表、校历、
开放规则、路线和天气落成可执行计划。大模型负责理解和自然表达，Python
负责时间计算、硬约束和版本化重排，知识库负责校园依据，外部接口负责
动态路线与天气。

本轮特别回归了以下容易出错的边界：

- “根据我的课表安排……”仍进入规划，不被误判为课表问答；
- 非连续课程节次能够形成多个独立硬约束；
- 夜间降雨不会因只读取白天预报而漏掉；
- 高德同名地点优先选择杭电校区结果；
- 图书馆不同楼层、快递点、校医院、阳光长跑和体育馆规则不串台；
- 学生手册中的休学期限、申诉期限和例外条件不被模型改写；
- 新问题不会误用上一轮旧计划；
- 多轮新增、删除、改时长和整体顺延只改变应变动部分。
- 周分配只有通过课表、开放时间、通勤和天气校验后才写入日程；
- 新任务插入周计划时可保持原有效时间块，并建立版本和血缘链；
- 专门反例验证“只移动冲突任务”优于会连带移动两项的逐项贪心。

## 八、预期结果

### 当前参赛目标

- 让学生使用一段自然语言得到可执行、无硬冲突的日程；
- 在复杂课程、地点、开放时间和天气条件下减少人工反复调整；
- 面对突发变化时尽量保留原计划；
- 让制度和服务时间问答有明确依据；
- 通过个人课表、记忆和提醒形成连续使用价值。

### 当前证据边界与轻量后续

- 当前不把暑假期间难以组织的“30 名以上不同年级学生试用”写成已完成成果；
- 现阶段用冻结场景、基线对比、消融实验、接口回归和逐案例报告证明算法行为；
- 若提交前仍有时间，只做少量真实任务走查并保留原始记录，不从小样本外推
  “满意率”或“普适准确率”；
- 用户研究、长期留存和提醒有效性属于后续产品验证，不与当前技术指标混写；
- 正式长期运营仍需迁移国内云服务器和持久化数据库。

## 十、当前边界与答辩口径

- 当前服务对象固定为杭电下沙校区，不宣称已经服务全国高校；
- 高德电动车专用路线额度不足时会降级为普通骑行参考或保守估算，并明确
  提示数据来源；
- 天气信息不可用时不会虚构晴雨，只会继续完成与天气无关的规划；
- Vercel 临时存储不等同于正式持久化数据库；
- 浏览器通知依赖用户授权，关闭网页后的可靠提醒依靠导出的系统日历；
- 测试通过代表已覆盖场景达到预期，不应表述为“所有可能输入零错误”。

答辩时应重点讲：这不是通用聊天助手，而是“可验证的校园时空决策引擎”；
核心证据是周—日分层落地、硬约束零违反、事件后最小扰动、版本可追溯和
可复现基线/消融。不要把冻结基准包装成真人试用，也不要承诺国奖结果。
