# 杭电知识底座与个人数据

当前版本固定服务于杭州电子科技大学下沙校区。产品目标不是泛化到所有
学校，而是把本校课程作息、场馆服务、校园通勤、制度问答和学生日常关照
做深、做准、做成稳定可验证的智能体能力。

## 一、本校公共知识

`data/` 中的公共数据由项目维护，所有用户共享：

```text
data/
├── campus_profile.json      # 杭电下沙校区、时区与高德查询参数
├── locations.json           # 本校地点、别名、类别与已核验坐标
├── travel_times.json        # 实时接口不可用时的本校路线快照
├── opening_hours.json       # 图书馆、快递点、宿舍、场馆和校医院
├── campus_rules.json        # 阳光长跑、热水、餐厅和服务规则
├── class_periods.json       # 第1至13节课的准确时间与拥堵时段
├── academic_calendar.json   # 法定节假日和调休基础数据
└── knowledge/
    ├── official/            # 2025年学生手册等正式制度
    └── curated/             # 已核验的本校服务时间知识
```

学校知识不是都交给大模型“理解”。时间、开放时段、门禁、节次和活动有效
时段先结构化为确定性规则，用于硬约束校验；学生手册和解释性材料通过
增强检索提供依据与出处。

## 二、每位用户单独维护的数据

学校规则相同，但每个人的时间和习惯不同。以下数据按 `user_id` 隔离保存：

- 个人课表：课程名、星期、节次、教学周、地点和学期起止；
- 临时校历：停课、补课和按其他星期上课；
- 长期偏好：缓冲时间、步行节奏、交通方式、常用地点等；
- 个性化习惯：用户主动开启后才用于提出建议；
- 日计划、周目标、完成记录和历史版本。

个人课表可以从杭电教务系统 PDF 导入，也支持 Excel、CSV、JSON。包含
教学周的课表必须填写“第一教学周周一”，系统据此换算单双周和真实日期。
导入完成后，课程会作为不可移动的个人硬约束。

## 三、周规划中的数据优先级

1. 用户本轮明确指定的固定时间、截止时间和锁定任务；
2. 用户启用的个人课表与临时停课/补课；
3. 已核验的杭电结构化时间规则；
4. 高德实时路线、天气和本校 POI；
5. 用户主动启用的长期偏好与习惯建议；
6. 学生手册与本校服务知识检索结果；
7. 仅供解释或风险提示的经验性建议。

低优先级偏好不能覆盖高优先级硬约束。例如“喜欢晚上自习”不能覆盖晚课，
“常用图书馆”不能被套用到跑步、取快递或就医任务。

## 四、地图和天气

高德配置由 `campus_profile.json` 提供：

```json
{
  "external_services": {
    "amap": {
      "search_city": "杭州",
      "campus_query": "杭州电子科技大学下沙校区",
      "weather_adcode": "330114"
    }
  }
}
```

API Key 只保存在部署环境变量中。地点名称明确时，优先使用高德返回的本校
POI 坐标；“实验室”“食堂”等泛称先结合本校地点别名，仍不明确时询问
用户。路线接口失败时可使用本校已核验路线快照或坐标估算，但必须标注
数据来源。天气不可用时不猜测，不阻断基础规划。

## 五、维护与验收

更新本校知识后运行：

```powershell
& D:\APP\Dev\Python\envs\yicheng-agent\Scripts\python.exe scripts\validate_static_data.py
& D:\APP\Dev\Python\envs\yicheng-agent\Scripts\python.exe -m pytest -q
```

当前静态数据验收应至少保证：

- 地点 ID、开放时间和活动规则引用一致；
- 第1至13节课时间完整且不重叠；
- 24:00、法定节假日、单双周等边界能正确解析；
- 阳光长跑“场地开放”和“可计入时段”严格区分；
- 学生手册检索结果保留来源，结构化硬规则优先于普通文本。
