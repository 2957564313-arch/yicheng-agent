## 验收目的

单个接口成功不能证明应用可以连续使用。本验收以真实公网地址为对象，把
用户在页面中的连续操作串成完整旅程，验证数据能否在多个请求之间正确
衔接，并检查用户最终看到的中文内容，而不只检查 HTTP 状态码。

## 本轮发现并修复的问题

### 1. 普通案例误用天气调整话术

离线演示天气数据会被三个 Demo 共享。案例一虽然没有完成天气重排，
回答却曾声称“已经避开风险时段”。现已增加计划事实校验：只有户外任务
确实结束在天气风险边界之前，系统才能使用天气调整话术。

### 2. 健康接口缺少稳定服务标识

健康接口原先只有版本、数据库和能力状态，不便于公网监控确认当前响应
是否来自正确应用。现增加：

```json
{
  "service": "yicheng-agent",
  "display_name": "易程智策"
}
```

### 3. 周计划执行事件字段契约不一致

周计划分配使用 `earliest_start` 和 `latest_end` 表示可执行时间块。验收
脚本最初错误使用 `start_at`，导致完成事件缺少时间。脚本已按公开响应
模型修正，并验证重复事件不会二次扣减目标时长。

### 4. 服务时间问句被误当成安排任务

“顺丰几点关闭”“周末校医院几点可以就诊”等问句曾因包含快递、就诊
关键词而被创建为计划任务。现已优先识别“几点/什么时候 + 开放、关闭、
营业、就诊、计入”等规则问句，直接从已核验知识回答并附依据来源。

### 5. 任务级截止时间错误扩散

在“参加会议，之后取快递，18点前完成，再去自习”中，18:00 曾被错误
解释为全天所有任务的截止时间，导致自习被判为不可行。现已区分句末的
整体截止时间、带“全部/所有”的整体截止时间，以及紧邻某项任务的局部
截止时间。

### 6. 冲突解释缺少当天门禁边界

夜间洗澡与宿舍门禁冲突时，旧回复只说明热水时段，没有把周日 23:00
门禁说清楚。现会把目标日期实际适用的场所开放窗口加入冲突原因。

### 7. 开放式求助缺少关怀和输入引导

面对“最近事情有点多，帮我安排一下”，系统不再只机械索要任务，而是先
接住用户的压力，再引导用户按“任务、最晚完成时间、预计时长、地点”
逐项补充；不确定字段可以留空，由系统继续协助梳理。

### 8. 公网临时存储缺少跨设备迁移路径

Vercel 临时运行环境可能在服务更新后重置数据，仅依靠浏览器快照无法把
课表与习惯带到新设备。现已加入个人数据包：

- 导出个人课表、长期记忆、校历调整、提醒设置、当前计划与习惯历史；
- 不导出测试密码、登录令牌或任何 API 密钥；
- 恢复前预览数据数量，明确提示课表覆盖规则；
- 恢复失败不清空当前设备旧数据；
- 恢复后重新验证课程硬约束、就寝提醒和长期日程。

### 9. 电动车路径规划单项额度达到上限

高德电动车路径规划 v5 单项额度达到上限后，旧逻辑会直接落到本地估算。
现改为三级容错：先请求电动车实时路线，失败后尝试高德普通骑行路线作为
保守参考，再失败才使用本地路线或坐标估算。发生降级时会在回答和页面提醒
中说明，不会伪装成电动车实时精确结果。步行、普通骑行、地点搜索和天气
仍独立工作。

### 10. 公网跨实例时个人数据偶发缺失

Vercel 的 SQLite 位于临时实例。旧流程把创建记忆、导入课表、恢复数据和
读取日程拆成多个仅依赖服务端状态的请求；当请求落到不同实例时，日程可能
漏掉刚刚恢复的长期记忆或课表。

现已把浏览器本机快照设为公开测试版的个人数据事实来源：

- 日程汇总、到点提醒和系统日历导出都携带个人上下文；
- 同一次请求内同步课表、记忆、校历、提醒设置与当前计划后再计算；
- 同一快照重复执行不会重复写入相同计划；
- 用户在浏览器删除的数据不会被旧临时实例重新带回；
- 个人数据恢复旅程不再假设两个请求必然命中同一实例。

这解决了单台设备在公网临时部署中的连续体验，但不替代正式持久化数据库。

### 11. 课表与规则问句的意图边界不稳定

“根据我的课表帮我安排……”曾因出现“课表”而进入知识问答，“我明天
有哪些课”又可能被误当成新规划；校医院、阳光长跑和体育馆开放问句也
可能被解析成活动任务。现已把“查询已有课程”“引用课表参与规划”和
“查询校园运营规则”分开识别，并加入公网连续场景回归。

### 12. 精确制度答案可能被模型自然改写

学生手册已经检索到正确的“两年、创业休学除外”，但模型润色可能改变
句式、来源格式，极端情况下还可能改变关键数字。现对学生学籍、处分、
请假、休学、申诉、转专业等已核验规则启用确定性回答：保留直接条款、
例外条件、原文件页码和章节，不允许模型覆盖事实。公网新增休学期限场景
已通过。

### 13. 夜间天气与同名地点选择边界

天气提醒曾只检查首个预报时段，存在“白天多云、夜间有雨”时漏掉带伞
提醒的风险；地点搜索也曾直接取高德第一个同名结果。现会综合当天全部
有效预报时段，并按当前校园名称与地址对候选地点重排，降低选中校外同名
建筑的概率。

## 可复现命令

```bash
YICHENG_BASE_URL=https://yicheng-agent.vercel.app \
node scripts/public_product_acceptance.mjs
```

若公网启用测试账号：

```bash
YICHENG_BASE_URL=https://yicheng-agent.vercel.app \
YICHENG_USERNAME=测试账号 \
YICHENG_PASSWORD=测试密码 \
node scripts/public_product_acceptance.mjs
```

脚本使用带时间戳的隔离用户，避免与真实体验用户的数据互相覆盖；三个
比赛 Demo 在测试前后都会复位。

## 与其他质量门的关系

产品旅程验收不能替代其他测试。当前发布门由四层共同组成：

1. 251 项 Python 自动化测试：函数、仓储、规则和接口边界；
2. 100 例离线评估：常规规划、知识问答、时间硬约束、降级、
   澄清、固定 Demo 与关怀韧性；
3. 28 个公网复杂场景 + 15 个连续状态场景：模型、地图、天气和多轮状态；
4. 8 条产品级公网旅程：页面能力背后的完整业务闭环。

任意一层失败，都不能把对应版本作为比赛稳定版本。

## 已知边界

当前 Vercel 版本用于公网测试，SQLite 位于临时目录。快速连续请求已经
通过；长期日程、到点提醒和系统日历会在单个请求中重新同步浏览器个人
快照，因此不再依赖前后请求命中同一实例。这仍不能证明跨设备和长期运行
的数据持久性：个人数据包提供主动备份与跨设备迁移，正式长期运营前仍应
迁移至持久化数据库或具备持久化磁盘的服务器。
